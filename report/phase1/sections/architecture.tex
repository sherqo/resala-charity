\section{Design and architecture}

The system follows an MVC structure. Screens display data and collect user actions. Controllers receive these actions and pass them to services. Services apply the business rules and use repository interfaces to read and write data. The repository implementations contain the storage details.

The same structure supports both interfaces. The graphical interface and the console interface use the same controllers and services, so a business rule is written once and behaves identically in both. This is the practical proof of the MVC boundary.

\subsection{One operation across all layers}

When a donation is recorded, the screen collects the form values, the controller passes the request to the donation service, and the service applies the rules and asks the factory to create the correct donation. The repository saves the result, the service notifies its observers, and the screen refreshes. The console interface performs the same operation through the same controller and service, so no rule is duplicated between the two interfaces.
